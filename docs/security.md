# الأمان وحدود الإصدار

الشبكة المحلية تقلل التعرض الخارجي، لكنها لا تلغي مخاطر الأجهزة المصابة أو الحسابات المسروقة أو موظف يتجاوز صلاحياته. لا يمكن ضمان إغلاق كل ثغرة؛ يلزم مراجعة مستقلة وتهيئة التشغيل واختبار قبول قبل بيانات المرضى الحقيقية.

## ما يطبقه الكود

- فحص الجلسة والدور في الخادم لكل قراءة وعملية، وإعادة الفحص داخل المعاملة قبل الكتابة.
- مخططات `z.strictObject` وواجهات Zod 4 الحديثة، ومنها `z.email` و`z.uuid` و`z.iso.date`؛ لا ثقة بمدخلات المتصفح.
- رفض مصادر وHost غير متوقعة، وفحص Fetch Metadata، وطلبات JSON محدودة الحجم والوقت. منع POST غير الضروري إلى الصفحات.
- ملفات تعريف ارتباط HttpOnly وSameSite Strict وSecure عند HTTPS، ورموز جلسة عشوائية تخزن بصمتها فقط. انتهاء الجلسة بعد `5` دقائق دون نشاط أو `8` ساعات إجمالًا.
- كلمات مرور لا تقل عن `12` محرفًا، رفض أنماط شائعة، اشتقاق scrypt بملح عشوائي، وحدود لمحاولات الدخول والعمليات الحساسة والطلبات المتزامنة.
- الدخول باسم المستخدم وكلمة المرور وتحديد الصلاحيات من دور الحساب المخزن. تغيير كلمة المرور إلزامي عند أول دخول، وتغيير كلمة المرور وتعطيل الحسابات يتطلبان كلمة المرور الحالية. الدخول التجريبي دون كلمة مرور يتطلب `NODE_ENV=development` و`NOUR_TEST_LOGIN=true`، ويستخدم حسابات منفصلة؛ لا تُقبل جلساتها خارج هذا الوضع.
- CSP مع nonce، منع التأطير، منع تخمين نوع المحتوى، وسياسة إحالة وذاكرة مؤقتة ملائمة لبيانات حساسة. لا استخدام لـ dangerouslySetInnerHTML لمدخلات المستخدم.
- أسعار من قاعدة البيانات، معاملات ذرية، إصدارات للسجلات ومفاتيح لمنع تكرار العمليات، وأرصدة صحيحة دون كسور عائمة.
- هوية تشغيل PostgreSQL محدودة؛ لا صلاحية superuser أو إنشاء قواعد/أدوار. تمنع صلاحيات SQL تعديل/حذف الدفعات والحركات والتدقيق بواسطة التطبيق.
- تسجيل قراءات الملفات والعمليات المهمة، دون تسجيل كلمات المرور أو محتويات النماذج في سجل الأخطاء. إشعارات التحديث لا تحمل ملفات طبية.
- نسخ AES-256-GCM، تحقق من سلامة النسخة قبل الاستعادة، وتجربة استعادة إلى قاعدة مولدة منفصلة.

الاختبارات الآلية تتحقق من حدود محددة، ولا تعادل اختبار اختراق شاملًا. `npm audit` يكتشف الثغرات المنشورة المعروفة فقط.

## المطلوب عند التثبيت

HTTPS داخلي موثوق، وكيل موثوق يعيد كتابة X-Real-IP، جدار ناري لشبكة الموظفين فقط، قاعدة غير مكشوفة للشبكة، حسابات نظام محدودة، تشفير القرص، تحديثات أمنية دورية عبر وسيط موثوق، قفل أجهزة الموظفين، UPS، نسخ خارج قرص الخادم، وجدولة مع تنبيهات ومراجعة سجل. لا تعرض منفذ Next أو PostgreSQL مباشرة للعملاء. استثنِ شبكة الضيوف والأجهزة الطبية غير الموثوقة.

ملفات `.env.migrate` و`.env.setup` و`.env.backup` ومفتاح فك النسخ وبيانات الاسترداد تخص المسؤول فقط؛ صلاحية `mode: 600` لا تكفي وحدها على Windows، ويجب ضبط NTFS ACL. لا تتركها في مجلد قابل للقراءة بواسطة حساب خدمة الويب. إعدادات التطوير ليست إعدادات الإنتاج.

## ما لا يتضمنه الإصدار

لا سحابة أو مزامنة خارجية، ولا عمل مستقل دون الشبكة المحلية، ولا وصفات أو تشخيصات أو تأمين أو محاسبة مزدوجة. لا مرتجعات مالية بعد التحصيل، ولا دفع إلكتروني فعلي؛ اختيار البطاقة/التحويل يوثّق وسيلة الدفع فقط. لا تعقب صلاحية الدواء والدفعات والأرقام التسلسلية؛ المخزون الحالي للمستلزمات العامة، وليس نظام صيدلية متكاملًا. لا حذف فعلي للسجلات المالية من الواجهة.

لا يوجد تسجيل مستخدم ذاتي، أو استرداد بالبريد، أو CAPTCHA، أو تكامل أجهزة. إعادة تفعيل موظف معطل ليست متاحة في الواجهة الحالية. سياسة الاحتفاظ بالبيانات والإيصالات، الإجراءات عند الوفاة/الخروج قبل السداد، وسياسات الاسترداد المالي تحتاج اعتماد المنشأة وتطويرها قبل استخدامها إن كانت ضمن التشغيل المطلوب.
